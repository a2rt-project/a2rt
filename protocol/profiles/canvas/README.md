# Canvas Profile：当前架构适配要求

状态：适配要求，尚未发布对应的新 Profile 机器定义；日期：2026-11-16。本页基于[当前 A2RT 规范](../../README.md)，记录 Canvas 已确认的领域选择，不定义 A2RT 的通用事件枚举。

## 1. 轨道与同步组织

Canvas 使用六条领域轨道，并配置必选且唯一的 system 输入轨道。以下列出用途及角色／方向；实际轨道 ID、格式 ID、时钟参数与内容 Schema 由 Canvas 的版本化配置确认。

| 用途 | role | direction |
| --- | --- | --- |
| assistant 音频 | assistant | output |
| assistant 操作事件 | assistant | output |
| user 音频 | user | input |
| user 已发生的操作事件 | user | input |
| 画布画面 | environment | input |
| 画布状态与执行结果 | environment | input |
| 系统通知 | system | input |

`environment` 是 Canvas 声明的扩展角色。六条领域轨道可以绑定到同一交互信息同步组，智能体端和环境端分别交付适用于自己的内容；不会因输入输出同组而相互等待。system 的信息同步组由 Canvas 选择，通知内容及具体分组需要在接入前确认。

本项目采用同步交付。后端按共同窗口组织画布画面、状态、音频及事件，Canvas 定义快照截止点、媒体覆盖、有效空值与保持、完整性判断及超时恢复规则。录像异步进行，不参与实时交付的就绪条件。

所有轨道都遵守每周期最多一个数据帧，以及窗口两端精确映射到整数根刻度的 Core 约束。轨道通过 `sync_group_id` 绑定同步组；交付规则放入 `delivery_policy`，编码容量与各接收端队列上限放入 `limits`。

## 2. 双方操作与教学表现

- user 与 assistant 每个 actor 同时最多执行一个任务；两者可以各自执行一个任务，user 的本地输入不等待模型反馈。
- 指针操作逐事件表达开始、移动、释放或取消；同一 actor 的指针任务与工具任务不能交错执行。
- 音频可以与画布任务同时进行；一次输出结束、一次操作任务结束与整个会话结束分别判断。
- 使用画布原生协作者光标和选择辅助，保留选中框、锚点及可见操作过程；反馈状态提供选中元素与组的标识。
- 对象冲突沿用 Excalidraw 的协调机制；本 Profile 不增加对象锁。

事件名称、工具封装、参数、任务与输出标识、状态和结果 Schema 由 Canvas 定义，并通过轨道的 `media_type + constraints` 契约声明。通用文档中的示例事件不直接成为 Canvas 的接口。

## 3. 实现所需的绑定

接入前需确认时钟树、同步组、轨道与格式目录，落实整数根刻度映射、每轨单帧、共享容量及接收队列限制。Canvas 适配器负责真实编辑执行、音画呈现映射、状态与画面的版本一致性、完整观察判定，以及取消、重连和恢复后的对账。

system 只承载可信协调器的输入通知；模型请求和输出边界走 assistant 输出轨道。协调器实际执行中断和清理，不等待通知与媒体配齐后才处理。
