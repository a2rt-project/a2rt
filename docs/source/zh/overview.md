# 协议概览

智能体一边讲话、一边操作时，环境也在持续变化：用户可以介入，工具可以仍在运行，声音与画面可能先后到达。A2RT 为这些过程提供共同的消息语义。

## 六条逻辑轨道

| 标准标识 | 内容 |
| --- | --- |
| `assistant.audio` | 智能体音频、显式静音与缺口 |
| `assistant.events` | 智能体操作请求、工具调用与无操作决策 |
| `environment.audio` | 人、设备和其他参与者的声音 |
| `environment.events` | 已发生的输入和系统事件 |
| `environment.visual` | 截图、视频帧或协商过的视觉表示 |
| `environment.state` | 执行回执、领域状态、控制结果和播放进度 |

轨道是信息分类。一条轨道可以包含多个具名 stream，它们不需要使用相同的连接、帧率或采样率。基础闭环注册 `assistant.events`，以及在 `environment.state` 中分别承载 `core.result` 与 `core.control_result` 的 stream；其他能力按清单启用。

## 就绪即交付

反馈不需要凑齐六条轨道。音频已就绪而视觉仍在生成时，可以先交付声音。画面晚到后保留自己的来源时间和关联状态版本，不覆盖已经确认更新的状态。

同步是局部的：某个操作声明对齐音频采样位置时，等待这组依赖就绪，不把等待扩展到整个会话。

## 请求与事实分开

`output.event` 表示执行请求；环境中的 `core.result` 报告真实结果。`accepted` 表示接纳，`running` 表示执行推进，二者均不等于完成。模型不能自行宣称执行成功。

`environment.events` 使用同一个 Event 结构记录已经发生的事实。观察到的人类操作不能再次交给执行器执行。

## Core、Profile、Adapter、Binding

Core 固定身份、生命周期、时间和回执。Profile 声明环境的事件、状态、工具与执行策略。Adapter 对接真实应用。Binding 负责鉴权、交付与资源寻址。

A2RT 不绑定画布、模型厂商或 MCP。MCP 可以作为可选工具接入方式，但需要适配器和明确的映射。详见[核心规范](spec/01-core-and-profiles.md)。

## 当前边界

0.2 是不兼容旧版的草案修订。规范没有固定 10 fps、100 ms 窗口或统一音频采样率，也没有硬实时截止保证。性能与恢复质量属于具体实现的工程验收。
